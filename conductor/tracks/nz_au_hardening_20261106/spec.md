# Hardening specification

Mature and tidy the existing repository without rewriting history, removing other work,
publishing private artefacts or introducing duplicate quality infrastructure. Reuse existing
Scorecard, security, CI and dependency receipts when exact source/environment scope matches.

Acceptance: README and Conductor agree with actual capability; live links/examples work;
public package contains only approved code/metadata; Apache-2.0 and third-party notices are
correct; clean-install and declared entry points work; CI permissions/actions/cache boundaries
are justified; logs exclude secrets; schemas reject malformed/stale inputs; recovery works;
performance is measured under resource limits; open findings have evidence-based disposition.

GitHub cleanup includes review of description/topics/homepage, README navigation/badges,
CITATION, SECURITY, contribution/setup instructions, issue/PR templates, workflow duplication,
release metadata and stale branch/issue inventory. Inventory is not authority to delete
branches, close others' issues, change visibility/security settings or remove archived evidence.
Native modifications require exact ownership and applicable authorization/readback.

No maximal security score, independent scientific endorsement or standards compliance is
claimed merely from passing tests or adding files. Preserve scientific and software gates.
